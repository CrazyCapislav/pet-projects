# Как разбирать этот код

План чтения проекта на неделю вечеров. Порядок не по папкам, а **по пути одного
запроса**: систему понимаешь, когда прослеживаешь путь насквозь, а не когда
читаешь пакет за пакетом.

Отмечай галочки по мере прохождения — так видно, где остановился.

---

## Подготовка (5 минут)

Включи логи SQL — это удваивает пользу от чтения. В `application.yml`:

```yaml
logging:
  level:
    dev.rahim.feedhub: DEBUG
    org.hibernate.SQL: DEBUG
    org.hibernate.orm.jdbc.bind: TRACE
```

Теперь на каждый запрос к API видно, какой именно SQL сгенерировал Hibernate.
Самый быстрый способ понять JPA — не читать про неё, а смотреть, во что она
превращается.

Запусти приложение и держи запущенным всё время чтения:

```bash
./gradlew bootRun --console=plain
```

## Три приёма, без которых чтение не работает

**1. Держи приложение запущенным.** Прочитал файл — сходи потыкай
соответствующую ручку и посмотри в логи. Связь «код ↔ поведение» закрепляется
только так.

**2. На каждый файл задавай вопрос: «что сломается, если это убрать?»**
Нет ответа — значит, просмотрел, а не понял. Часть ответов проверяется руками:
закомментируй `@EntityGraph` в `ArticleRepository` и вызови `/api/articles`.
Увидишь `LazyInitializationException` вживую, а если поправить иначе — увидишь
и N+1: один запрос превратится в запрос плюс двадцать.

**3. Пройди отладчиком.** Поставь breakpoint в `FeedRefreshService.refreshOne`
и нажми «Обновить ленты» в интерфейсе. Пошагово увидишь, как выполнение уходит
в корутину и возвращается.
